# NormalTreeCapitator 1.0.3

Changelog since **1.0.2**.

---

## Highlights

- Tool-tier groups: the same woods can appear in multiple groups; the held axe picks which chain runs
- Config ownership: your `groups` and `block-damages` are no longer rewritten from the jar on `/tc reload`
- Low-durability axes: free foliage still breaks, and replant can top up saplings when leaves cost 0 durability
- Version & updates: `/normaltreecap version`, Pastebin update feed, clickable download links for staff

---

## Tool-aware block groups

Groups are now selected by **broken block + held tool**, not by “first group that lists the block.”

| Behavior | Detail |
|----------|--------|
| Matching | With `need-tool: true`, the first group that lists **both** the block and the tool wins |
| Overlaps | The same log/leaf may appear in several groups (e.g. `stone` vs `iron`) |
| Names | Group keys stay free-form (`stone`, `iron`, `Trees`, `Other`, …) |
| Empty groups | Groups with an empty `blocks` list are still skipped on load |

**Example**

```yaml
groups:
  stone:
    blocks:
      - minecraft:oak_log
      - minecraft:birch_log
    tools:
      - minecraft:stone_axe
  iron:
    blocks:
      - minecraft:oak_log
      - minecraft:birch_log
      - minecraft:dark_oak_log
      - minecraft:jungle_log
    tools:
      - minecraft:iron_axe
```

- Iron axe + oak → `iron` group → can chain into dark oak / jungle  
- Stone axe + oak → `stone` group → oak/birch only

## Config reload no longer restores deleted sections

On reload, jar defaults are still used to fill **new settings keys**, but these sections are fully user-owned and are **not** copied back from the jar:

- `groups:`
- `block-damages:`

You can remove or rename `Trees`, `Other`, `logs`, `leaves`, etc. — `/tc reload` will not put them back.

### Custom `block-damages` sections

Section names under `block-damages` are arbitrary labels. Each needs `damage` and a `blocks` list:

```yaml
block-damages:
  heavy_logs:
    damage: 2
    blocks:
      - minecraft:oak_log
  mushrooms:
    damage: 1
    blocks:
      - minecraft:mushroom_stem
```

Unlisted blocks still use built-in fallbacks (leaves/wart/shroomlight → `0`, everything else → `1`).

## Durability, leaves, and replant

When `break-tool: false` and the axe is low on durability:

1. Costly blocks (logs) are capped so the tool keeps 1 durability  
2. **0-cost** foliage is still included in the chain after that budget runs out  
3. If `replant` + `replant-consume-saplings` are on, and that species’ foliage costs **0** in `block-damages`, missing saplings are topped up in the drop pool so stumps can replant  
4. If foliage costs **more than 0**, no free saplings are granted

## Commands & aliases

| Addition | Detail |
|----------|--------|
| Alias | `/normaltreecap` (alongside `/tc`, `/treecap`, `/treecapitator`) |
| Subcommand | `/tc version` / `/normaltreecap version` |

`/version` shows the installed version, checks the remote feed, and if you are outdated shows a **clickable** download link.

## Update checker (Pastebin)

Remote version source:

- Paste: https://pastebin.com/nc6CbGem  
- Raw: https://pastebin.com/raw/nc6CbGem  

**Layout:** `version|download url`

```text
v1.0.3|https://modrinth.com/plugin/normal-tree-capitator/versions
```

| When | Who gets notified |
|------|-------------------|
| Plugin enable | Console warning + online ops / `normaltreecapitator.admin` |
| Player join | Ops and `normaltreecapitator.admin` |
| `/tc version` | Whoever ran the command |
| Every 3 hours | Online ops / admin permission |

Leading `v` on the remote version is supported. Local strings like `1.0.3 Build N` compare as `1.0.3`.

## Upgrade notes

1. Drop `NormalTreeCapitator-1.0.3.jar` into `plugins/` and **restart** (new alias + update checker need a restart).  
2. Run `/tc reload` if you want new message keys merged into an existing `messages.yml`.  
3. Existing custom `groups` / `block-damages` are safe — they will not be overwritten by the jar defaults.  
4. When you publish a newer release, update the Pastebin line to the new `version|url`.
